# 等保 2.0 三级自查清单（qiye-zhiku 私有化部署）

> 适用对象：企业智库 RAG 问答系统（FastAPI + ChromaDB/Milvus + Ollama）在央企/政企内网私有化部署时的等保 2.0 三级（GB/T 22239-2019）对照自查。
> 说明：系统侧已落实项标注 **已实现** 并给出对应模块；基础设施/管理侧项标注 **需现场整改**，属于部署环境与管理制度范畴。

## v1.4 快速验证命令

```bash
# 1) 生成自签证书并启用 HTTPS
python scripts/gen_self_signed_cert.py --cn 192.168.x.x
# 将 config-add.txt 内容追加到 config.yaml，重启后 https://ip:8000 访问

# 2) 验证脱敏（上传含手机号/身份证的文档 → 检索返回均为掩码）
# 3) 验证密码策略（注册弱密码 123456 应被拒绝）
# 4) 验证登录告警（连续 3 次错误密码 → 管理后台审计日志出现 security.alert）
```

## 常见问题（FAQ）

Q: 自签证书浏览器报"不安全"怎么办？ A: 等保验收建议使用客户单位已有 CA 签发的证书；自签证书仅用于联调环境，可将根证书导入终端信任库。

Q: 脱敏后检索准确率会下降吗？ A: 掩码保留前 3-6 位与后 4 位（如 `138****5678`），对号码类实体检索影响极小；若业务需要原始号码可关闭 `security.mask_sensitive`（不推荐）。

Q: HTTPS 与内网 HTTP 场景如何选择？ A: 等保 2.0 三级要求通信传输加密，内网建议同样启用 HTTPS；若内网隔离严格且合规允许，可保持 HTTP 并关闭公网暴露。
